# DB 생성·수정 시각과 향후 자료 정리

2026-10-18 사용자 요청: 생성 후 경과 기간 또는 마지막 수정 후 경과 기간을 기준으로 향후 자료 정리가 가능한 DB 구조를 준비한다. 이번 변경은 날짜 기록 기반이며 삭제 기능·보관 기간·삭제 대상은 확정하거나 실행하지 않는다.

## 공통 기록

업무 테이블 48개에 내부 관리용 `record_created_at`, `record_updated_at`을 추가한다. 기존 `created_at`, `updated_at`, `ended_at`, `resolved_at`, 만료 시각과 API DTO는 그대로 유지한다. Alembic 관리 테이블은 대상이 아니다.

- 새 행: PostgreSQL이 두 시각을 같은 생성 시각으로 자동 기록한다. 앱이나 직접 SQL 입력으로 과거 생성일을 위조하지 않는다.
- 기존 행 내용 변경: PostgreSQL trigger가 최종 수정 시각만 갱신한다. 생성 시각은 보존한다. ORM·일괄 SQL 모두 적용한다.
- 조회, 값이 동일한 UPDATE, 관리 시각만 바꾸는 UPDATE: 시각을 변경하지 않는다. 실패/rollback된 변경은 최종 수정 시각에도 남지 않는다.
- `timestamptz`로 절대 시각을 저장한다. 일수 비교는 DB 시계를 사용하며 화면에서 필요할 때 KST로 변환한다.
- 기존 행은 원래 `created_at`/`updated_at`이 있는 경우 해당 값을 복사한다. 그 외 과거 시각은 `NULL`로 남겨 알 수 없음을 보존한다. 이후 실제 수정부터 최종 수정 시각이 기록되며, 생성 시각을 수정일로 대체하지 않는다. 과거 `joined_at`/`started_at` 등을 생성일로 해석하는 별도 보완은 이번에 하지 않는다.

내부 필드이므로 Flutter DTO 변경이나 회원·소유권 version 증가는 없다. 수정 시각은 행의 실제 변경 시각이지 사용자 마지막 접속 시각은 아니다. 백그라운드 worker의 lease 변경 등도 실제 변경에 해당한다. 회원 비활성 기준이 필요하면 별도 로그인/활동 시각을 사용해야 한다.

## 나중에 정할 정리 정책

각 자료 종류에 대해 다음 중 하나를 선택할 수 있다.

- 생성 기준: `record_created_at < 현재시각 - N일`
- 최종 수정 기준: `record_updated_at < 현재시각 - N일`
- 인증·분쟁 종료 기준: 기존 `ended_at`/`resolved_at < 현재시각 - N일`

기준 시각이 `NULL`인 과거 자료는 자동 대상에서 제외한다. 날짜만으로 모든 테이블을 일괄 삭제하지 않는다. 실제 구현 시에는 자료 종류·진행/종료 상태·참조 관계·보존 대상·보관 기간을 정하고 대상 미리보기, 필요한 인덱스와 배치 처리를 추가한다. 현재 회원·소유권 등 유효한 행은 오래됐다는 이유만으로 삭제 대상으로 확정하지 않았다.

## 구현·적용

공통 ORM 정의: `app/auth/models.py`의 Base. 고정 DDL: `0016_record_timestamps`. 기존 행을 삭제하거나 기존 업무 필드를 바꾸지 않고 관리 필드만 추가·알려진 시각을 복사한다. downgrade로 기록을 버리지 않고 향후 forward migration을 사용한다.

새 테이블을 추가할 때 Base의 두 공통 열과 `record_timestamps_before_write` trigger를 해당 migration에 포함한다. trigger 함수는 DB에 공통으로 정의되어 있다. 전체 테이블의 공통 열/trigger 존재는 격리 PostgreSQL 시험으로 검사한다.
