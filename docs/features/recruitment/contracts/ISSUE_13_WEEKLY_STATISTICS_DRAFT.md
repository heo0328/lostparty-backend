# 사용자·그룹 주간 이용 통계 선행 계약안

현재 추적(2026-10-18): 통계 주제는 [Issue19](https://github.com/heo0328/lostparty-backend/issues/19)로 분리했다. 아래 #13/#12는 원요구/제안의 출처이며 앞으로 통계 검토·구현 회신은 #19에서 진행한다.

2026-10-17. 요구 원본: [#13 일곱 번째 Flutter](https://github.com/heo0328/lostparty-backend/issues/13#issuecomment-6232893737), [#12 열 번째 인계](https://github.com/heo0328/lostparty-backend/issues/12#issuecomment-6232896201). **설계 제안이며 통계 DB/HTTP/집계·방 API 구현 완료가 아니다.** 현재 한도/주간 개인완료/방 참가관계와 분리한다. 아래 귀속 시점과 조회 형식은 Backend 제안으로 구분한다.

## 확정 요구

- #10의 KST 수요일06시부터 다음 수요일06시 직전 `[start,end)`와 DB 서버 시각을 사용한다. 경계06시 이벤트는 새 주차다.
- 주중 한 번이라도 확정 참가한 고유 방/그룹을 사용자UUID에 기록한다. 이전부터 유지한 참가도 포함하고, 탈퇴/해산해도 이용이력은 남는다. 모든 원정대/캐릭터를 합산하고 생성자 중복은 없다.
- 사용자별 공개/그룹 방 이용수·그룹 이용수, 공개/그룹 완료·미완료종료 각각/합계와 각 결과 중 다음주 함께하기 활성수를 보존한다.
- 그룹별 실제 생성한 그룹전용 방 수와 주차/회차 완료·미완료종료 및 함께하기 활성수를 방별로 센다. 회원통계 합산은 하지 않는다. 반복 새회차를 신규 방 생성으로 세지 않는다.
- 완료 안 된 해당 주 회차가 경계를 넘으면 미완료종료다. 명시 종료/주차 마감 원인을 구별한다. 이 집계로 현재 membership을 삭제하거나 실제 게임 클리어/개인 Claim을 만들지 않는다.
- 함께하기는 해당 주 마감06시 설정값을 보존한다. 마감 후 변경은 과거값을 덮지 않는다. 개인 수동체크는 모집 결과 통계에서 제외한다.

## 최소 원천 보존 제안

새로운 통계 전용 참가 명령을 만들지 않고 실제 도메인 명령의 transaction에 다음 원천 기록을 연결한다. 구조명은 제안이며 현재 migration에 추가하지 않는다.

1. 그룹/방 membership의 유효 구간 `[joined_at,ended_at)`과 사용자UUID·그룹/room/round UUID. 동일 관계 재가입은 새 구간으로 기록하고 과거를 덮지 않는다. G1 현재 membership 행만으로 향후 재가입 이력을 덮어쓰지 않도록 G2 이전에 구간/이벤트를 연결한다.
2. room 실제 생성시각·생성 당시 공개유형/그룹UUID의 불변 snapshot. 공개↔그룹·연결변경은 유효시각과 서버 revision을 가진 이력으로 남긴다.
3. round의 room/cycle/회차번호·시작/마감, 결과 `completed|incomplete_ended`, 원천 `explicit_complete|explicit_end|cycle_close`, 발생시각·결과당시 분류/그룹·참가자UUID snapshot. room+cycle+round 결과는1개이며 재처리로 다른 결과를 덮지 않는다. 명시 결과가 이미 있으면 주차 마감 결과를 중복 생성하지 않는다.
4. 함께하기 설정의 유효시각 이력과 방 종료 이력. 마감 뒤의 현재 설정만 읽어서 과거를 복원하지 않는다.
5. 통계 원천 지원 시작시각/지원 분야, 집계 revision·마감 watermark·잠정/확정/실패/누락 상태. 최초 지원 이전을 임의로0으로 채우지 않는다.

원천은 서버 시각/UUID·idempotency/도메인 revision에 묶고 명령과 함께 commit/rollback한다. 개인정보·외부 프로필 원문·기기키는 저장하지 않는다. 통계 원천을 이유로 기존 인증/원정대 자료를 이관하거나 초기화하지 않는다.

## 귀속 시점 제안 (검토 대상)

- 사용자 주중 이용의 dedup 키는 `(user,room,cycle)`, 그룹 이용은 `(user,group,cycle)`다. 경계 이전부터 유효한 구간과 해당 주차가 겹치면 미접속이어도 이용한다. 종료시각이 정확히 시작경계인 과거 구간은 새주에 포함하지 않는다.
- 공개/그룹 이용 분류는 그 주 해당 방의 **최초 유효 참가 시점** snapshot에 고정하는 안이다. 중도 전환으로 같은 방을 이용수 양쪽에 중복 가산하지 않는다. 원천에는 전환 이력을 남기므로 나중에 다른 분석은 가능하다.
- 완료/미완료 결과는 **결과 발생시점**의 분류/그룹과 확정 참가자에게 귀속한다. 먼저 탈퇴한 사람에게 후속 완료를 가산하지 않는다. 완료 후 탈퇴해도 이미 받은 결과는 보존한다. 마감 미완료는 경계 직전 유효 참가자 기준이다. 이용 분류와 결과 분류는 시점이 다를 수 있으므로 이용수=결과합계로 강제하지 않는다.
- 그룹 생성수는 생성 당시 그룹전용/연결 그룹에 귀속한다. 나중 공개전환/다른그룹 연결이 과거 생성 실적을 이동시키지 않는다. 그룹 결과는 결과 당시 그룹전용/그룹UUID snapshot에 귀속한다. 반복의 기존 방 이용/결과는 기록하되 실제 생성수는0이다.
- 결과의 함께하기 활성수는 그 결과 방이 경계 직전 종료되지 않았고 설정이ON인 경우로 제안한다. 사용자별은 해당 사용자의 현재 참가도 마감 시점까지 유지한 경우에 센다. 이미 해산된 방은 과거 ON이어도 실효값 false다. 완료 후 마감 전 변경은 반영하고 경계 후 설정 변경은 다음 주 이력이다. 결과유형/귀속 사용자/그룹은 다시 분류하지 않는다.
- 같은 room에 한 주 여러 회차를 허용할지는 실제 #13 회차계약에서 명시한다. 원천은 room+cycle+round를 보존하되 이용수는 고유room이며 결과수는 회차 기준이다. 기존 개인 주간 Claim/중복참가 차단을 통계 때문에 완화하지 않는다.

## 마감·재처리 제안

실제 회차명령과 마감은 동일 방/주차 직렬화 및 기존 game-mutations 락 순서를 따른다. 최종 DB시각이 경계를 넘은 명령은 현재 주차를 다시 검증한다. 마감 결과와 회차전환을 원자화하되 현재 참가관계/한도는 주차로 초기화하지 않는다.

worker가 늦게 실행되더라도 경계시각으로 유효 구간·설정 이력을 재생한다. 미처리 주차를 순서대로 마감하며 각 `(room,cycle,round)` 결과와 `(subject,cycle,aggregation_version)` 산출물을 유일하게 upsert한다. 재실행은 중복을 만들지 않고 이미 확정된 snapshot은 수정하지 않는다. 원천오류 수정은 별도 감사·집계revision으로 구별한다. 통계 실패는 재처리 상태로 기록하며 잘못된0/성공으로 응답하지 않는다. 집계 캐시가 현재 방 권한/진행을 결정하지 않는다.

## 보관·조회 계약 제안

- 사용자 주차별 원장: user UUID+cycle+집계revision, 공개/그룹 이용수, 고유그룹수, 각 유형 완료/미완료수, 각 결과 함께하기 활성수. 합계는 두 원천에서 계산한다.
- 그룹 주차별 원장: group UUID+cycle+집계revision, 실제 생성수, 완료/미완료수, 각 결과 함께하기 활성수. 그룹 결과를 참가자 수만큼 더하지 않는다.
- 각 산출물은 `starts_at,ends_at,state(provisional|final|unavailable|failed),coverage(full|partial|none),aggregation_revision,evaluated_at,source_complete_through`를 갖는 안이다. 미지원/실패 숫자는null, 실제 관찰된0만0이다. 평균은 full/final 주차만 기본 분모에 포함하며 부분 주차/누락은 제외 수를 함께 반환한다.
- 미래 HTTP안: `GET /v1/me/weekly-usage-statistics`, `GET /v1/me/groups/{group_id}/weekly-usage-statistics`, `from_cycle/to_cycle/cursor/limit`. 기본 최신완료주차, 최대범위/페이지 제한과 strict DTO/오류는 구현 전 최종 제안한다. 이번 OpenAPI에 추가하지 않는다.
- 본인 조회만 허용하고 타회원UUID 입력은 받지 않는다. 그룹 통계는 현재 유효 그룹회원 권한으로 집계수치만 보여주는 안이다. 전 회원의 UUID 명단/개인통계는 노출하지 않는다. 탈퇴 후에도 본인 과거 집계는 보존되지만 그룹 상세 조회권한은 이어받지 않는다. 내부 분석은 별도 서버 권한 경계이며 일반회원 쓰기/API나 새 운영자role은 제공하지 않는다.

## 독립 작업 순서·검증

1. 지금: 제한 명세 정정/L0 구현과 별도로 이 선행 설계를 게시한다. 통계 영향으로 L0/G1 전체를 보류하지 않는다.
2. G1/G2: 실제 생성/가입/종료 명령에 group UUID·회원 유효구간·이벤트를 동일transaction에 기록한다. 기존 사용자 주간통계를 가짜로 소급 생성하지 않는다.
3. #13 방/회차: 방 생성·공개변경·참가 구간·결과 snapshot·함께하기 이력부터 보존하고 현재 점유/권한과 연결한다.
4. 해당 원천이 갖춰진 뒤 마감/재처리·사용자/그룹 집계와 조회 API를 구현·검증·게시한다. 통계 UI/BM/운영 배포는 포함하지 않는다.

향후 검증: 경계직전/정각·미접속/지연여러주·중복마감·생성참가중복·탈퇴재가입·유형전환·전참가자의결과비귀속·완료후설정변경·해산방OFF·반복신규생성0·부분실패rollback·수동체크제외·현재한도불변·타회원/탈퇴후그룹접근거부·지원이전null. 현재는 이 통계 테스트/실제 통계 API를 실행한 결과가 아니다.
