## 최신 회신 — 전체149번째 Flutter / 조건부 소비 수용

2026-10-25 [전체149번째 Flutter 소비 대조](https://github.com/heo0328/lostparty-backend/issues/13#issuecomment-6393878499)를 확인했다. 제안1의 구조·사용자확정4항목·프로필/원ACK·일정/예약/표·검색·표시권한·메모snapshot/계정프리셋은 수용됐고, **최종 문자정책과 operation별 완결 wire를 보완한 고정본 확인 전까지 조건부 수용**이다. 구현/서버 반영 승인은 아니다.

최신 전달은 제안1의 emoji/EGC/Unicode17 제안보다 우선한다. 신청메모와 저장문구에 동일 적용한다.

- NFC 후 한글완성형 U+AC00~D7A3, 호환자모 U+3131~3163, ASCII 영문/숫자, U+0020, 기호 `.,!?~()-_/@#&+`만 허용한다.
- 앞뒤 U+0020만 제거한 뒤 내부공백 포함 코드포인트20자. NFC로 한글이 되는 분해입력은 정상화한 뒤 검사하며, 허용 밖 문자를 조용히 지워 다른 문장으로 보내지 않는다. emoji/VS/ZWJ·허용 밖 결합문자/전각/탭/개행/제어문자는 거절한다.
- 신청 생략/null/빈내용은 없음, 프리셋 빈항목은 불가. 기존 byte/request 상한·정규화 전 원본문 digest는 유지한다. Unicode17 EGC 정합/emoji 허용 제안은 대체되며 원 제안문/schema/벡터는 고정안2 파트에서 함께 변경했다.
- 욕설/성적표현 금칙어는 앱 로컬 패키지·한국어 사전으로 검사한다. 서버 금칙어 검사/사전 API/동기화/키입력별 통신은 추가하지 않는다. 서버는 실제 신청/저장 시 허용문자/길이·원래 권한/정합성을 검증한다. 로컬 필터를 위조클라이언트 차단 보장으로 주장하지 않는다.

다음 Backend 보완: 제안문/schema/공통벡터 수정, operation별 완결 요청·응답/오류·reader_profile 조합·record content=null·identity null/권한·memo 위치·candidates/review 포함 profile 전달 경로·구클라이언트 차단/안전 관리명령 목록을 고정한다. 기존 envelope 전체를 소비할 예시가 필요하며 신규component 예시만으로 전체 wire 합의를 완료했다고 표시하지 않는다.

Flutter는 현재 Controller의 원요청 보존이 메모리이고 Gateway.write가 query를 전달하지 않는다는 점을 보고했다. operation/method/path/query/profile/T/원본문/key 영속 복구 보완이 필요하며 완료 상태가 아니다. C+N은 각각의 기본시각/조율값, N단독 next_* 금지·임의7일 복사금지와 context 바인딩을 수용했다.

수신확인 단계에서는 기록만 누적했다. 후속 사용자 “작업 진행합니다” 승인으로 **베타 계약 최종 고정·소비 인계**를 진행해 최신문자/완결 wire·예시/호환목록을 작성·정적검증했다. 서버 구현/실제반영은 포함하지 않으며 문자25벡터는 실행했지만 HTTP/DB 기능시험은 아니다. 아래 초안의 EGC/emoji 제안은 당시 이력으로만 보존한다.

## 검증 사례의 정확한 상태

아래는 **요청된 기대 결과/앞으로 작성할 검증 기준**이다. 이번 베타 기능의 통과 결과나 기존 격리시험 수로 표시하지 않는다.

- 목 생성·토18기본·추가2명·리더포함3명/금20공통이면 금20확정. 조기후보없으면 토18유지. 토17:30기한에 인원미달/리더단독이어도 기본확정. 이미조기확정이면 원기한/개인표변경으로 이동 없음.
- 기한정각·지연·중복 worker,가입/승인/탈퇴/표갱신 경합,마감 후 신규증가 차단·최초임계합류예외,예약 중복생성/원ACK재송·C/N/종료/해산 격리.
- 전체미설정/부분구간/조회실패 구분·pending자동공급없음·실제가입/표복사원자성·다른예약/점검·진행시간 보존·확정약속 임의이동없음.
- 동시발급/원키재송 추가발급없음·C/N별도·N→C불변·선행0·비참가자/pending/반대T참가자의 표시2값 누출없음.
- 메모없음/20자/초과·저장0~5/위조6개,본인권한/공개누출·기기간동시수정·프리셋변경후옛신청불변·원본문재송/중복신청방지.

20자 단위는 사용자 인지 문자/단일행·trim·빈내용=메모없음이 Flutter 추천이다. emoji/조합문자·줄바꿈/제어문자와 정확 규칙은 아직 닫힌 wire가 아니다. Python len을 곧바로 확정 규칙으로 쓰지 않는다. 자동조율 OFF 기본값도 고정 설계에서 제안값으로 구분돼 있어 계약 제안에 명시해야 한다.

## 계약 작업 진행안 — 사용자 토의 전 검토안

아래는 2026-10-25 후속 검토 때 제시한 추천안이다. 이후 사용자가1·2·4를 채택했고3의 지연 사례를 설명받은 뒤3도 채택했다. 네 가지 제품 결정은 확정이며 구체 wire는 [Backend 제안1](beta-contract-proposal.md)로 Flutter 소비 대조한다. 실행 계약/구현 완료는 아니다. 구현·Issue 답변 전에 실제 제품 공백만 토의한다. 새 확정 출발 필수/추가인원·동의분모/기한fallback·미설정/메모범위를 다시 질문하지 않는다.

### 작업 파트와 완료 조건

1. **베타 일정·표시 계약 제안:** 기본약속/실제확정·조율상태·기한/권한·원자적인 표복사·검색/읽기·번호를 하나의 일관된 상태 전이와 요청/응답 예시로 정리한다. 현재API·validator/트랜잭션 재사용과 새 모델/호환 범위를 명시한다. 사용자 토의 결과를 반영해 Flutter에 소비대조 가능한 제안으로 인계하는 것이 이 파트의 완료 조건이다.
2. **신청 메모·계정 프리셋 계약 제안:** 원문snapshot·20자공통규칙·본인최대5개/기기간CAS·목록/단건/본인권한·기존 무메모/원ACK를 별도 완료조건으로 묶는다. 일정과 독립적인 작업량/후속 추적이 커지면 전용Issue 분리를 검토하되 같은 목적브랜치를 유지한다. 이번 토의에서 즉시 이슈를 만들거나 구현하지 않는다.
3. **소비대조 이후 구현·인계:** 합의된 구간만 구현→격리 자격/원자성·경계시험/두계약검증→구간 커밋/push·원격확인→인계. 실제 개발 반영은 대상·자료보존을 확인하는 별도 구간이다. 매 채팅이나 세부질문마다 마감하지 않는다.

### Backend가 기술안으로 정할 부분

- 기존 C/N·generation·권한/CAS·원키/원본문/원ACK를 재사용한다. 성공가입과 개인표 복사는 한 트랜잭션에 둔다. pending에서는 복사·실제점유를 만들지 않는다. 최신 개인표의 없음/빈표/부분표/조회실패를 구별하며 표출처 revision을 저장한다.
- 기본출발/기한과 실제확정을 구분해 저장한다. worker만 기다리지 않고 신규 가입·승인/표변경 등 관련 명령에서도 현재 DB시각과 기한을 검사/정합 처리해 정각 이후 틈을 막는다. 저장된 원ACK 재생을 새 마감 판정으로 거절하지 않는다. 중복 worker/재송은 확정·예약을 중복 생성하지 않는다.
- 날짜/시간대/상태 필터를 SQL페이지 이전에 적용하고 cursor조건에 묶는다. 시각은UTC전송/KST표시·주차 의미를 유지하고 시작포함/끝제외·자정/주차 경계 예시를 Flutter와 대조한다. 필드명/nullable/생략·오류 code/상태는 Backend가 폐쇄 DTO 제안으로 정한다.
- 저장문구는 회원 소유 별도 자원으로 검토하고 기존nice_group설정의전체PUT/버전을 무관하게 공유하지 않는 안을 우선한다. 최대5개 전체 목록의 원자 저장·revision/CAS와 명령 멱등을 재사용하면 삭제/수정/순서·동시변경을 관리할 수 있다. endpoint 자체는 아직 확정하지 않는다.
- 메모는 제출문자열을 저장하며 프리셋 ID를 역참조하지 않는다. 권한 있는공대장/본인조회에만 제공하고 공개·다른참가자 조회에는 제외한다. 입력생략/빈문구는기존무메모와호환되게 제안한다.
- 20자는 Flutter추천에 맞춰 화면에서 한 문자로 보이는 단위(extended grapheme cluster)·한줄·앞뒤공백제거/빈내용없음으로 제안한다. 이모지 결합에 쓰이는 ZWJ 등을 제어문자라는 이유로 일괄 삭제하지 않는다. 줄바꿈·나머지 제어문자 처리와 Unicode분할 버전/공통시험예제는 양측에서 맞춘다. [Unicode UAX29](https://www.unicode.org/reports/tr29/)가 기술 기준이며 사용자가 라이브러리/코드포인트를 선택할 필요는 없다.

### 사용자와 토의할 제품 영향 4항목

| 항목 | 현 인계의 공백 | 추천안과 사용자 영향 |
|---|---|---|
| 조율중 기본약속의 시간 점유 | 기본시각은 약속이지만 조기미확정기간에 다른방 자동조율의 busy로 잡을지는 명시되지 않았다 | **실제참가 순간 기본시간도 약속예약으로 잡는다.** 자기방 조기탐색에서는 그 자기예약을 제외하고, 조기확정 시 기본예약→실제예약을 원자 교체한다. 다른방 자동조율은 약속을 피하며 직접제안/본인중복수락 허용은 유지한다. 자동조율 가능한 시간이 줄 수 있지만 기본약속을 무시한 겹침을 줄인다. |
| 참가자가 있는 방에서 자동조율 ON/OFF | 생성시기본OFF는추천이고 중도활성화의 확인/즉시효과가 명시되지 않았다 | **기본OFF, 미확정·마감전 공대장만 ON/OFF.** ON 전 즉시 앞당겨질 수 있음을 확인하고 현재 방 제출표/실제인원으로 즉시 평가한다. 조건미달이면 기본약속유지. 이미확정한시각은토글로지우거나되돌리지않고 기존 일정제안/동의경로를 따른다. 참가자추가투표를 새로 강제하는 안은 아니다. |

네 가지 추천은 사용자 채택 완료다. 다른 기술 항목은 Backend 제안1의 예시/오류·필수필드로 정리했고 Flutter가 실제 소비/UX 차이를 확인한다. 대화마다 따로 게시하지 않고 지침 명확화와 사용자 결정·제안/정적검증을 같은 계약 인계 파트로 묶는다.
